`gh` is GitHub CLI. The Nibfin extension adds the `nibfin` command group.
The examples below use the public **candidate CLI**. Formal release and
fresh-user installation remain Unverified. Follow the
[candidate build guide][candidate] to install from reviewed source.

Replace `OWNER/REPO` with the public repository you want to work on, such as
`octocat/hello-world`. Use your existing GitHub CLI login.

## Get help

```sh
gh nibfin help
```

## Check prerequisites

```sh
gh nibfin preflight --repo OWNER/REPO
```

This read-only check reports host tools, login presence, Docker observations,
and repository permissions. It reports observations and gaps, not security
certification or successful Issue execution. Desktop discovery is separate from
native guest verification; see [execution environments](../execution-environments/)
and [preflight details][preflight].

## Preview and propose setup

Preview the changes first. With repository and workflow write permissions,
you can then open the installation PR and add any missing workflow labels.

On compatible native Linux/systemd hosts, plain init uses managed onboarding.
The [installation walkthrough](../installation/) owns consent, merge polling,
automatic continuation, original-intent resume and readiness interpretation.
Explicit `--consent-managed-login` supplies the host login-reuse consent decision;
it does not grant repository or local administrator permissions.

The paired `--runner-directory` and `--runner-name` flags select legacy optional
registration. That path requires a repository administrator to rerun apply after
merge. Explicit shared-service and Wake options also retain manual behavior;
keep them separate from managed init. See
[registration paths](../runners/#registration-paths).

## Agent selection and pool replacement

Fresh managed pools default to Codex. Init accepts `--agent` for explicit
selection; existing pools preserve their binding when omitted and peers inherit
it. Both slots share one provider/model/profile. A conflicting selection requires
explicit managed replacement rather than ordinary init. Claude installation is
Planned because production composition is unavailable, even though the parser
recognizes its name. See [Agent providers](../agent-providers/) for source-backed
Codex candidate examples and authentication differences.

The maintained `runner rebuild` interface previews whole-pool replacement;
`--apply` and `--consent-rebuild` separately authorize applying or resuming it.
Use the [replacement guide](../agent-providers/#explicit-pool-replacement) inside
the managed Linux host. Core settlement and final activation govern progress.
Individual unregister/remove do not retire a pool or switch its provider.

## Credential renewal and disconnect

GitHub CLI reauthentication or [scope refresh][gh-refresh] changes the local gh
login, not an already imported Controller credential. Sign in again using the
same intended GitHub member and compatible Codex account when renewal is needed.
Repeating init on an adopted host does not replace adopted credentials, and this
CLI has no dedicated reauthorization command.

The installed root-only Core `managed-credentials` administration interface owns
`status`, `replace`, `disconnect` and fresh `intake`. A local administrator uses
that verified installed interface for same-member renewal, invoking
`/opt/nibfin/core/bin/nibfin-core.mjs` with the installed pinned Node runtime.
Replacement requires active managed state and settled consumers/effects. Follow the
[maintained credential guide][credentials] and its private producer integration;
do not construct credential envelopes manually or pass tokens through arguments,
environment variables, repositories, Runner or Agent inputs. Unsupported active
Codex authentication needs the dedicated Controller login path.

Disconnect stops new admissions and removes only Controller-managed credentials
after active leases and effects settle. Unknown processes or writes remain
Pending; do not force deletion to finish it. It does not revoke provider grants
or remove the original gh/Codex stores. After completed disconnect, reconnection
uses fresh same-member intake. To revoke provider access, use GitHub's authorized
application/token controls and the corresponding Codex provider controls.
[GitHub CLI logout][gh-logout] alone does not revoke an imported token.

## Manage Runners

```sh
gh nibfin runner list --repo OWNER/REPO
```

Repository administrators can use the `runner` subcommands below. Omit
`--apply` to preview changes.

| Subcommand | What it does |
| --- | --- |
| `create` | Downloads and verifies the official GitHub Runner package. |
| `register` | Registers a prepared Runner with the repository. |
| `list` | Lists repository Runners. |
| `unregister` | Removes registration and reconciles local Runner configuration. |
| `remove` | Removes the remote registration and keeps local Runner files. |

See the [Runner command guide][runner] for exact flags and the
[team-member quick registration guide][quick] for the separate `init --quick`
handoff. Its steps are `request`, `issue`, `register`, `confirm`, and `reconcile`.
Use `inspect` and `cancel` for recovery.

## Local Dashboard

permission-checked Pause and Resume requests.

```sh
gh nibfin dashboard --repo OWNER/REPO
```

The Dashboard uses your current GitHub CLI identity and opens in a browser.
It shows the request result and the observed GitHub label. Core's effective
decision is displayed as Unknown. Press Ctrl+C in the terminal to stop it.
See [pause and resume](../lifecycle/#pause-and-resume)
and the [Dashboard guide][dashboard].

### Mobile access

Tailscale is optional. Install and use Nibfin, run your Runners, and open the
Dashboard on your computer with your existing GitHub CLI login.

Remote Dashboard access via Tailscale Serve is planned. The current Dashboard
accepts connections from the computer running it. A phone on the same Wi-Fi
cannot open that local address.

If you want to prepare for remote access, install Tailscale on the computer and
phone and sign in to the same private Tailscale network. When remote Dashboard
access is available, Serve requires MagicDNS and HTTPS certificates for that
network. Tailscale can guide you through HTTPS setup the first time you enable
Serve. Keep the computer online while using the Dashboard from your phone.
See [Tailscale setup][tailscale-setup] and [Tailscale Serve][tailscale-serve].

## Preview an upgrade

```sh
gh nibfin upgrade --repo OWNER/REPO
```

Upgrade requires compatible official release metadata and assets. Once those
are available, `--apply` can open a PR for the managed workflow changes.
See the [upgrade guide][upgrade] for options and recovery.
