# Concurrent Issue delivery

The current authorized GitHub Issue is the requirements source. The protected
grant still selects the Issue, operations, roles and Core source. Its original
Scope body is historical. Line-ending changes, trailing whitespace, and equivalent JSON formatting in
the published obligations block preserve the current contract. A substantive body change requires fresh independent
Shape validation and evidence for the changed requirements.

Core captures the Writer checkout even if main advanced. The full Candidate
pins the original tree and base for reproducible hooks and publication. A
binary diff, paths, artifact identities and hook sources identify the delivered
content separately. A repair after a native conflict or branch-update
requirement may reuse existing content checks only if those inputs match.

Core opens a PR against the protected branch. Final Review verifies Candidate
content and PR identity. Merge separately requires current GitHub mergeability,
required checks, reviewers and effective protection. A green result for an
older integration base cannot authorize a newer integration. Core compares
the merged result to the verified integration tree and proves its ancestry
before closing the Issue. Uncertain external effects stay Pending.
